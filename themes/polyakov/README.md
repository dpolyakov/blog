# Polyakov

Самостоятельная тема для [Hugo](https://gohugo.io/).

## Запуск

Из корня блога:

```sh
hugo server --disableFastRender
hugo --gc --minify
hugo --buildDrafts --buildFuture --buildExpired --destination /tmp/blog-polyakov-all
```

Тема подключена через `theme = "polyakov"`. Посты берутся из `params.mainSections = ["blog"]`, размер страницы — `pagination.pagerSize`. Главная и страницы отдельных тегов/категорий показывают карточки, `/blog/` — архив по годам.

## Размеры карточек на главной

На каждой странице пагинации посты делятся на последовательные группы по пять. В каждой группе первый пост без ручного ограничения становится акцентным. Обложка `feature` определяет его оформление: с изображением — картинка слева и текст справа на широком экране, без изображения — крупный заголовок и анонс рядом. На планшетах и телефонах содержимое акцентной карточки располагается последовательно.

Размер можно задать в front matter публикации:

```yaml
cardSize: wide
```

| `cardSize` | Результат на главной |
| --- | --- |
| `auto` или поле отсутствует | Участие в автоматическом выборе акцента. |
| `normal` | Обычная карточка, исключённая из автоматического выбора. |
| `wide` | Акцентная карточка на всю строку. Заменяет автоматический акцент в своей пятёрке. |

Например, чтобы выделить второй пост вместо первого, достаточно добавить второму `cardSize: wide`. Несколько ручных `wide` в одной группе показываются все; автоматический акцент при этом не добавляется. Если у всех постов группы стоит `normal`, акцента не будет.

Обычные карточки идут по две в ряд; оставшаяся без пары занимает строку целиком. На мобильных все карточки занимают одну колонку. Порядок постов и число записей на странице не меняются. Правила размеров действуют только на главной и её страницах пагинации; карточки в категориях, тегах и связанных публикациях остаются обычными.

## Контент

Существующий front matter менять не нужно. Необязательная обложка задаётся полем `feature`: URL, путь от корня сайта или имя файла в page bundle. Без `feature` карточка и заголовок статьи остаются текстовыми; первая картинка автоматически обложкой не становится. Анонс карточки: `description`, затем стандартный Hugo summary (`summary`, `<!--more-->` или автоматическое сокращение).

Поддерживаются Markdown, таблицы, цитаты, списки задач, сноски, definition lists, inline code и fenced code blocks. Для подсветки укажите язык: `yaml`, `js`, `sh` и другие языки Chroma. Номера строк управляются `markup.highlight`; кнопка копирует только код. Палитры github / github-dark переключаются вместе с темой. Стили Chroma находятся в `assets/css/chroma.css`.

Страницы и посты используют общий лейаут: заголовок, необязательный тизер (`description`, затем явно заданный `summary`), обложка `feature` на ширину колонки и текст. Дата и время чтения показываются у постов. Автоматический summary в шапке не используется.

Автор в шапке по умолчанию скрыт. Чтобы показывать его на страницах и в постах, установите `displayAuthor = true` в секции `[params]`. При отсутствии настройки автор также скрыт.

Заголовки имеют якоря. Оглавление включается существующим `params.enableTOC`, отключается у отдельной страницы через `toc: false`. При ширине от 1100 px у страниц и постов одна сетка: 720 px для текста и 240 px для правого сайдбара, независимо от наличия оглавления. Оглавление закрепляется справа и выделяет текущий раздел; на узких экранах сворачивается перед текстом. Подпись Markdown-картинки задаётся её title: `![alt](image.jpg "Подпись")`; также поддерживается стандартный `figure` shortcode. Изображение без ссылки можно увеличить кликом и закрыть клавишей Escape.

Работают встроенные Hugo `figure`, `youtube`, `ref`, существующий проектный `admidad`, HTML video/audio и iframe. YouTube/Vimeo адаптируются по ширине, аудиовставки сохраняют заданную высоту. В проекте оставлен `markup.goldmark.renderer.unsafe = true` для существующего HTML. Формулы, Mermaid и комментарии не подключаются.

## Цветовая тема и доступность

Обе темы используют монохромную палитру интерфейса. Первый визит следует системной теме. Кнопка ☀/☾ сохраняет выбор в `localStorage.theme`; этот ключ совместим с прежним MemE. Без JavaScript сохраняются системная цветовая схема, навигация, контент и подсветка. Скрипт нужен для ручного переключения, мобильного раскрывающегося меню, копирования и увеличения изображений. Есть skip link, видимый keyboard focus и учёт `prefers-reduced-motion`.

## Совместимость

Сохраняются адреса статей и aliases, RSS `/rss.xml`, Atom `/atom.xml`, sitemap и `/search.json`. JSON-индекс использует прежние поля `uri`, `title`, `content`, а также включённые настройками `description`, `categories`, `tags` и необязательный `subtitle`. Настройки SEO и метаданные берутся из существующего конфига; Метрика подключается только в production-сборке.

Тема не использует шаблоны или ресурсы MemE. Проектные shortcode и render hook внешних ссылок остаются на уровне блога. Публикация и настройка hosting не входят в тему.

## Аналитика и JSON-LD

Счётчики подключаются независимо, если их ID заполнены в секции `[params]`:

```toml
[params]
    yandexMetrikaId = 912262
    gtagId = "G-XXXXXXXXXX"
```

Для отключения удалите соответствующее поле или оставьте его пустым (`""`). Метрика использует `clickmap`, `trackLinks` и `accurateTrackBounce`, а также пиксель внутри `body` для посетителей без JavaScript. Google tag загружается асинхронно и инициализируется через `gtag('config', ID)` по [официальному примеру](https://developers.google.com/tag-platform/gtagjs).

Аналитика включается только в production: обычная команда `hugo` или `hugo --environment production`. При `hugo server` счётчики отсутствуют; проверить production-превью можно командой `hugo server --environment production`.

У постов из `mainSections` автоматически формируется JSON-LD [schema.org/BlogPosting](https://schema.org/BlogPosting): заголовок, описание, канонический URL, автор, даты публикации и изменения, язык, раздел, число слов, теги и изображение. Автор берётся из существующего front matter и `data/author.toml` с запасным значением `params.author.name`; `displayAuthor` управляет только видимой подписью. Изображение использует ту же цепочку выбора, что и SEO-метаданные: `feature`, `images`, первая картинка при `autoDetectImages`, затем `siteLogo`. Новых обязательных полей нет.

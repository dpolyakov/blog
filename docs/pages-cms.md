# Редактирование блога в Pages CMS

Откройте [Pages CMS](https://app.pagescms.org/), войдите через GitHub и выберите
`dpolyakov/blog`. GitHub App достаточно предоставить доступ только к этому
репозиторию. Конфигурация находится в `.pages.yml` и действует в выбранной ветке.

## Ветки и публикация

1. Выберите `public`, затем в **Manage branches** создайте рабочую ветку и
   переключитесь в неё. Новая ветка создаётся от текущей открытой ветки.
2. Редактируйте любой набор статей и изображений. Каждое сохранение создаёт коммит
   в выбранной ветке. Рабочих веток может быть несколько.
3. На GitHub откройте pull request из рабочей ветки в `public`.
4. Проверьте изменения и результат **Check content / check**. Снимите флаг
   «Черновик» у статей, которые должны появиться на сайте.
5. Слейте PR. Существующий workflow соберёт сайт и загрузит его в Object Storage.

Сохранение в `public` сразу запускает публикацию, поэтому для правок используйте
рабочие ветки. Отдельного сайта предпросмотра нет. Проверка PR сообщает об ошибках;
защиту ветки и обязательность проверки задают настройки GitHub.

## Статьи

Раздел «Статьи» редактирует `content/blog`. Страницы «Обо мне» и другие отдельные
страницы в эту форму не входят.

Создавайте статью из корня раздела. Название папки получается транслитерацией
заголовка: «Привет, мир!» → `content/blog/privet-mir/index.md`. После первого
сохранения изменение заголовка не меняет адрес. Встроенная транслитерация имеет
особенности: `й` → `j`, `щ` → `sh`, `ё` → `yo`.

Новая статья — черновик. В форме доступны заголовок, дата и время с точностью до
минуты, описание, обложка, категории, теги и текст. У опубликованных старых статей
явно записано `draft: false`, чтобы CMS не подставляла значение нового черновика.
Дополнительные поля, включая `slug`, `aliases`, `author` и `id`, сохраняются через
`settings.content.merge: true`.

Для Markdown, HTML и Hugo-шорткодов используйте вкладку **Source** редактора.
Перед слиянием смотрите diff: визуальный редактор может менять форматирование
Markdown. Существующие шорткоды не заменяются настройкой CMS.

Если адрес уже занят, Pages CMS может создать `index-1.md` в существующей папке.
Проверка PR отклонит такую структуру. На GitHub переместите новую статью в отдельную
папку с уникальным адресом и именем файла `index.md`; повторите проверку.

## Изображения

Загружайте изображения в общую медиатеку `static/uploads`. CMS записывает ссылки
в виде `/uploads/имя-файла.jpg`. Обложка использует ту же медиатеку. Поддерживаются
JPEG, PNG, GIF, WebP и SVG.

При подключении перенесены все 92 изображения из папок статей, включая черновики,
и обновлены 93 ссылки. Имена файлов сохранены, исходные файлы удалены. Старые
прямые ссылки `/blog/…/изображение` больше не поддерживаются. Ранее загруженные
файлы в `static/uploads` и внешние изображения не менялись.

После слияния в `public` изображения доступны по прямым ссылкам, даже если статья
остаётся черновиком. Флаг «Черновик» скрывает статью, а не файлы в `static`.

## Проверка перед публикацией

Требуются Hugo Extended 0.168.0 и Python 3; дополнительных пакетов Python нет.

```sh
python3 scripts/check-content.py
hugo --gc --minify --destination /tmp/blog-production
hugo --buildDrafts --buildFuture --buildExpired --destination /tmp/blog-all
python3 scripts/check-content.py --site /tmp/blog-all
```

В PR эти команды выполняет `.github/workflows/content.yml`. Проверяются структура
`content/blog/<адрес>/index.md`, сборка production, сборка всех статей и ссылки на
файлы `/uploads` в полученном HTML. Старые ссылки других форматов и доступность
внешних сайтов в эту проверку не входят.
